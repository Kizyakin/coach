# Chess Coach 1.5 — Resilient DB + Instant Live Coach

## 1. База данных больше не может уронить приложение

PostgreSQL теперь **опционален**.

Если `DATABASE_URL` отсутствует, Render Postgres истёк или база временно недоступна:

- API всё равно запускается;
- Live Coach работает;
- партия против Stockfish работает;
- дебюты, уроки и тренировки работают;
- master library работает;
- недоступно только постоянное сохранение пользовательских данных.

`render.yaml` больше не создаёт обязательную Render Database. Старую expired DB можно оставить или удалить — API от неё не зависит.

`GET /api/health` показывает состояние отдельно:

```json
{
  "ok": true,
  "database": {"available": false, "kind": "unavailable"},
  "stockfish": {"running": true}
}
```

## 2. FAST Live Coach

По умолчанию Live Coach запускается в режиме `FAST`.

Что изменено:

- Stockfish теперь запускается **один раз** вместе с backend и остаётся живым;
- раньше новый процесс Stockfish создавался на каждый анализ;
- FAST использует жёсткий лимит примерно `0.12 s` на анализ движка;
- FAST анализирует 3 лучших кандидата вместо 8;
- повторный запрос той же позиции берётся из RAM-кэша;
- большой Master Games поиск не блокирует первый FAST-ответ;
- health check больше не загружает master library;
- в игре против движка убран лишний двойной анализ промежуточной позиции;
- убрана искусственная пауза перед ответом движка.

Режимы:

- `FAST` — Live Coach, минимальная задержка;
- `NORMAL` — больше вариантов + мастерские аналогии;
- `DEEP` — более длинный анализ.

После ответа интерфейс показывает реальное серверное время вида `READY // 180 MS`.

> Первый запрос после сна Render Free всё равно может быть медленным: это cold start самой платформы. После пробуждения следующие ответы должны быть намного быстрее.

## 3. Совместимость

Старые запросы с `depth` продолжают поддерживаться. Новый рекомендуемый параметр:

```json
{"speed":"fast"}
```

## Обновление

Замени содержимое локальной папки проекта этой версией, не удаляя `.git`, затем:

```bash
git add .
git commit -m "Resilient database and instant live coach"
git push
```

После Blueprint sync база Render больше не нужна. Если в API останется старый `DATABASE_URL`, это не страшно: при ошибке подключения persistence просто отключится, а приложение продолжит работу.
